[khuda 싹쓸이 감지 with SAM3] 빠른 Baseline Plan

0) 프로젝트 이해(요약)
- 입력: 냉장고 내부 영상
- 목표: 사람이 냉장고에서 물체(음식)를 2개 이상 가져가면 “싹쓸이(1)”, 아니면 “정상(0)” 이진 분류
- 핵심: “가져간 물체 개수”를 영상에서 추정

1) 제안 룰 평가(가능/리스크)
1.1 핵심 아이디어(타당)
- SAM3로 “손(좌/우)” + “냉장고 내부 물체들”을 세그먼트/트래킹
- 손 마스크와 물체 마스크가 일정 시간 겹치고(접촉), 두 마스크의 이동 방향/속도가 유사하면 “잡았다(grasp)”로 간주
- grasp 상태에서 물체가 냉장고 내부 ROI를 벗어나면 “가져감(take)” 이벤트로 카운트
- take 이벤트가 2회 이상(=서로 다른 물체 2개 이상) 발생하면 싹쓸이로 판정

1.2 장점(왜 baseline으로 좋나)
- 학습 없이(또는 최소 학습) 바로 검증 가능: 규칙 기반 + SAM3 추론
- “한 손에 2개” / “양손에 2개” 케이스를 자연스럽게 처리 가능: 이벤트를 “손-물체 쌍” 단위로 세면 됨

1.3 주요 실패 케이스(미리 알고 가기)
- 손이 물체 위를 지나가며 잠깐 겹치지만 실제로 잡지 않는 경우(hover) → 오탐
- 물체가 서로 가까워서 마스크가 합쳐지거나 ID가 바뀌는 경우 → 중복/누락 카운트
- 냉장고 문/선반/조명 반사 등으로 세그먼트가 흔들리는 경우 → 가짜 접촉/가짜 이동
- “가져감”을 ROI 이탈로만 정의하면, 카메라 시야 밖으로 나가지 않고 손이 들고만 있어도 놓칠 수 있음

2) Baseline 정의(룰을 코드로 고정)
2.1 마스크 종류
- Hand masks: left hand / right hand (가능하면 2개로 분리, 안 되면 “hands” 전체로 시작)
- Object masks: “objects inside the fridge”로 내부 물체 다중 인스턴스
- Fridge-ROI: (옵션 A) 영상에서 고정 박스/폴리곤 수동 지정(가장 빠름)
            (옵션 B) SAM3로 “inside of the fridge”를 1회 세그먼트해서 ROI로 사용

2.2 grasp 판정(프레임 t에서, hand h와 object o에 대해)
- 접촉 조건: IoU(hand_mask[h,t], obj_mask[o,t]) >= T_iou 를 k 프레임 연속 만족
- 동조 이동 조건: v_hand = c(h,t)-c(h,t-1), v_obj = c(o,t)-c(o,t-1)
  - cosine(v_hand, v_obj) >= T_cos, 그리고 | |v_hand|-|v_obj| | <= T_speed
- grasp 시작 시점: 위 조건이 최초로 성립한 프레임
- grasp 해제 시점: 접촉이 m 프레임 연속 끊기거나(또는 v 동조가 붕괴) 하면 종료

2.3 take 이벤트(“가져감” 카운트)
- 이벤트 트리거(추천): grasp 상태인 object o가 냉장고 내부 ROI 밖으로 “중심점” 또는 “마스크 면적의 일정 비율”이 이동
  - inside_ratio(o,t) = area(obj_mask[o,t] ∩ ROI) / area(obj_mask[o,t])
  - inside_ratio가 T_inside 미만으로 떨어지고 그 상태가 r 프레임 유지되면 take=1
- 중복 방지: 같은 object_id(o)에 대해 take는 1회만 카운트(재진입/재접촉은 무시)
- 다중 동시 take 처리:
  - 한 손이 동시에 2개를 잡으면 (h,o1), (h,o2)가 모두 grasp→take 될 수 있음(=2개 카운트)
  - 양손이면 (hL,o1), (hR,o2)로 각각 카운트

2.4 최종 판정
- take_count >= 2 → label=1(싹쓸이), else label=0(정상)

3) 구현 단계(최소 기능부터)
3.1 데이터/입출력 정리
- 입력: `data/` 내 mp4 파일들(예: `data/example.MP4`)
- 출력(필수):
  - video 단위: take_count, 판정 라벨, 이벤트 발생 프레임 목록
  - (디버그) 프레임별 오버레이 영상/이미지: 손/물체 마스크 + ROI + 이벤트 텍스트

3.2 SAM3 추론 파이프라인(빠른 PoC)
- 1차(가장 단순): `sam3_ex.py` 흐름을 확장
  - 세션 1: text="hands" (또는 "left hand", "right hand"를 각각 시도)
  - 세션 2: text="objects inside the fridge"
  - 각 프레임마다 masks/object_ids를 받아 후처리(아래 3.3) 수행
- 속도 최적화(필요 시):
  - 프레임 다운샘플링(예: 30fps→10fps) 후 이벤트는 프레임 보간 없이도 1차 검증 가능
  - ROI 밖은 무시하도록 후처리에서 obj 후보를 줄이기(inside_ratio로 필터)

3.3 후처리(룰 계산 모듈)
- 프레임마다 다음을 계산/저장:
  - 각 hand/object 마스크의 중심점 c(*,t), 면적 area(*,t)
  - IoU(h,o,t), inside_ratio(o,t)
  - 속도 벡터 v_hand, v_obj
- 상태 머신:
  - pair (h,o)별로 contact_streak, grasp_active, take_done 플래그 관리
  - take 이벤트 발생 시 take_count++ 및 기록

3.4 결과 시각화(디버깅 필수)
- 오버레이 렌더:
  - 손(초록), 물체(파랑), grasp 중인 물체(빨강), ROI 경계(노랑)
  - 좌상단: frame_idx, take_count, 현재 grasp pair 수
- 저장 옵션:
  - 짧은 클립 1~3개만 우선 저장(속도/용량 절약)

4) 빠른 검증 실험 설계
4.1 최소 검증 세트 만들기(수작업)
- 영상 5~10개 선정(정상/싹쓸이 섞기)
- 각 영상에 대해 “실제 가져간 개수”와 “가져간 순간 프레임 대략”만 간단히 기록(csv 한 장)

4.2 평가 지표
- 영상 단위: Accuracy, Precision/Recall(F1) for 싹쓸이(=label 1)
- 이벤트 단위(가능하면): take_count 오차(예: MAE), 이벤트 검출 정밀도/재현율

4.3 파라미터 튜닝 루프(수동 그리드)
- T_iou(예: 0.02~0.10), k(예: 2~5프레임)
- T_cos(예: 0.7~0.95), T_speed(예: 픽셀/프레임 기준 허용치)
- T_inside(예: 0.3~0.7), r(예: 2~5프레임)
- 프레임샘플링 fps(예: 5/10/15)

5) 리스크 대응(필요 시 2차 개선 아이디어)
- hover 오탐 감소: “접촉 + 동조”에 더해 “손이 물체 위에서 닫히는(면적 변화)” 같은 신호(가능하면) 추가
- ID switch 대응: object_id가 바뀌어도 이전 마스크와 IoU가 큰 새 id를 같은 트랙으로 합치기(간단 re-ID)
- ROI 보강: 냉장고 문이 열릴 때만 이벤트를 허용(문 상태 추정이 가능하면)
- 손 분리가 안 되면: hand를 1개로 두고, (hand, object) 단위 이벤트만 먼저 검증

6) 이번 주(또는 1~2일) ToDo 제안(실행 순서)
- (1) ROI를 “고정 박스”로 먼저 두고, 한 영상에서 take 이벤트가 2개 이상 잡히는지 확인
- (2) 오버레이 디버그 영상 저장까지 완료(파라미터 조절이 빨라짐)
- (3) 영상 5~10개로 간단 평가표 작성 + 파라미터 튜닝
- (4) 실패 케이스 top3를 모아 룰 보강(hover/ID switch/ROI)
